## За что заплачено

Ревизия 4 закрывает KI-4: повтор ключа в событии больше не даёт два одноимённых
ключа в JSON, а сворачивается в массив. Для этого разбор обязан **обнаруживать
повтор**, чего в rev 3 не делалось вовсе — отсюда неустранимая часть накладных.

## Как искали

Первая сборка rev 4 дала 2121 МБ/с у Go (−24% к базе). Разложение по шагам:

| Вариант | МБ/с | Вывод |
|---|---:|---|
| rev 3 (база) | 2787 | — |
| rev 4, обнаружение отключено | 2751 | перестройка эмиссии заголовка и запись следов полей стоят ~1% |
| rev 4, попарная сверка имён O(N²) | 2174 | **обнаружение стоило 21%** |
| rev 4, скретч вместо массива на стеке | 2174 → +2.5% | зануление ~2 КБ на событие было не главным |
| rev 4, фильтр сигнатур O(N) | 2484 | таблица сигнатур с поколениями вместо O(N²) |
| rev 4, сигнатуры считаются при записи следов | **2570** | убран второй проход по следам |

Итоговая схема обнаружения: сигнатура имени за O(1) (длина + первый/последний/
средний байт) кладётся в таблицу на 128 слотов; поколение `gen` заменяет
обнуление таблицы. Совпадение сигнатур — лишь повод для точной сверки, которая
запускается редко (в корпусе `_PSI` реальные повторы были в 0.2% событий).
Тот же фильтр перенесён в C++ (`NdScratch`) и Rust (`RefScratch`).
